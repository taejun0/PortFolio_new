# Study room prototype

경로: `/test/mainpage`. 기존 포트폴리오와 분리한 로컬 실험 화면이다.

## 화면 검토와 우선순위 (2026-11-02)

실제 데스크톱·모바일 화면을 보고 다음 세 부분을 우선 수정했다.

- **모바일 오작동:** 390×844에서 공책의 `+` 중심을 눌러도 마우스가 작동했다. 사물을 넓힌 사각형의 모서리가 겹쳤기 때문이다. 실제 사물 다각형에 지름 44px 원을 합친 터치 영역으로 바꾸고, 모든 표시 중심이 자신의 버튼에 닿는지 확인했다. 화면 밖으로 거의 잘린 연필꽂이에 여백만 남아 표시되던 문제도 실제 그림의 가시 영역을 기준으로 제외했다.
- **표시의 우선순위:** 모니터·공책·인물의 주요 콘텐츠 표시는 더 선명하게, 다른 소품은 작게 조정했다. 클릭 대상은 유지하며 기능 설명의 이동 화살표는 제거했다.
- **소품 화면 크기:** 액자·사진·도구·경험 화면을 각각의 내용에 맞는 너비와 높이로 조정했다. 액자는 760px에서 440px, 사진은 540px 너비로 줄였다. 사진·액자를 열 때 방의 가림도 줄였다.

다음 디자인 작업의 우선순위:

1. **사물과 내용의 의미 연결.** 화분 → 경험은 예상하기 어렵고, 벽 메모와 인물은 같은 소개로 연결된다. 경험은 벽의 기록에, 식물은 만지는 반응에 연결하는 등 역할을 다시 잡을 필요가 있다.
2. **사물에서 내용으로 이어지는 전환.** 현재 크기는 다듬었지만 여전히 공통 패널이 나타나는 방식이다. 사진을 가까이 들여다보고 공책을 펼치는 등 선택한 사물에서 시작하는 전환이 다음 큰 작업이다.

이번 확인은 재현된 터치 문제, 표시 위치, 소품 패널에 한정했다. 회귀 항목도 실제 공책·마우스 터치 충돌 한 건만 기존 검사에 추가했다.

## 클릭 대상 안내 (2026-10-30)

처음부터 누를 수 있는 사물에 작은 원형 `+`와 옅은 윤곽을 표시한다. 마우스를 올리거나 Tab 키로 이동하면 해당 물건의 윤곽과 짧은 기능 이름이 나타난다. 조명의 기능 이름은 현재 켜짐 상태에 맞춰 바뀐다.

오른쪽 아래 **클릭 표시** 버튼으로 전체 표시를 켜고 끈다. 표시를 꺼도 클릭과 개별 hover·키보드 안내는 유지한다. 내용이 열리면 배경의 `+`와 도움말은 숨긴다. 모바일은 사물 표시를 보고 한 번 터치하면 바로 동작한다. 장식 문구나 상시 텍스트 라벨은 추가하지 않는다.

## 사물 탐색 확대 (2026-10-30)

클릭 대상을 5개에서 15개로 확대했다. 창문·커튼의 바람 기능과 클릭 표시는 사용자 요청으로 제거했다. 상시 메모지·라벨은 추가하지 않고 기존 그림의 사물 윤곽을 사용한다. 화면 크롭으로 가려진 사물은 클릭 대상에서도 제외한다.

- 스탠드: 책상에 따뜻한 조명을 켜고 끈다.
- 커피 잔: 김이 올라오고, 인물은 진행 중인 자세를 마친 뒤 잠시 타이핑을 쉰다.
- 키보드: 손과 화면의 짧은 타이핑 반응. 마우스: 실제 프로젝트 이미지를 모니터에 순환 표시하며, 모니터를 누르면 해당 상세를 연다.
- 앞쪽 식물: 잎을 건드리는 반응. 책상 화분: 기존 경험 전체를 읽는다.
- 벽 사진: 기존 사진 두 장을 넘겨 본다. 식물 액자: 그림 속 액자를 확대한다.
- 연필꽂이·창가 책: 기존 기술 스택을 펼쳐 본다.

조명 상태는 장면 내부에서만 관리하고, 사진·도구·경험도 같은 방 안에서 연다. 기존 이미지와 콘텐츠를 재사용하며 새 패키지·API는 없다. 캐시된 배경의 `onLoad`가 hydration 이전에 끝나는 경우는 디코딩 완료 시 `currentSrc`를 읽어 보완한다. 이 실제 오류에 대해서만 기존 검사에 회귀 항목을 덧붙였다.

## 방 안에서 읽기 (2026-10-30)

프로젝트와 글을 선택해도 기존 `/projects`·`/blog` 페이지로 이동하지 않는다. 같은 방 위의 모니터 화면·기록장 안에서 상세를 읽고 목록으로 돌아온다. 닫으면 그대로 방에 머문다. 소개도 프로필과 경험을 이 안에서 읽는다. 기존 페이지 자체는 유지한다.

- `RoomReaders.tsx`: 프로젝트 목록·상세, 글 목록·본문, 소개·경험. 표시할 내용은 기존 프로젝트 상수·About 상수·로컬 마크다운에서 가져온다. 새 소개 문구는 쓰지 않는다.
- 프로젝트는 6개를 방 안에서 탐색한다. 글은 기존 큐레이션의 로컬 글 본문을 기존 Markdown 변환기로 읽어 온다. 별도 API나 새 패키지를 추가하지 않았다.
- 상세에서 목록으로 돌아오면 이전 목록 스크롤과 선택 항목의 포커스를 복원한다. Escape는 상세 → 목록 → 방 순서다.
- 사물은 그림의 절대 좌표 다각형으로 등록한다. 화면 가장자리에서 잘려도 원래 윤곽 좌표를 유지하고, 마우스 클릭도 같은 다각형을 따른다. 터치는 작은 영역에 44px 여유를 제공한다.
- 읽기 화면의 너비와 높이를 고정된 범위로 잡아 목록·상세를 바꿀 때 패널 형태가 급격히 변하지 않도록 했다. 배경 방은 그대로 보인다.
- 코드 저장소와 글 안의 참고 링크는 사용자가 선택할 때 새 창으로 열어 방을 유지한다.

확인은 사물 클릭, 프로젝트·글 읽기 중 주소 유지, 목록 복귀·닫기, 모바일 터치에 한정했다. 실제 보고된 기존 화면으로의 이동 문제에 대해서만 기존 검사 파일에 주소 유지 확인을 추가했다. `npm run build`와 TypeScript 검사도 통과했다.

## 물건과 메모 (2026-10-30)

방에 별도의 포스트잇 메뉴를 붙이지 않는다. 원래 그림의 사물 자체가 클릭 대상이며, 마우스·키보드 포커스 또는 선택 상태에서만 물건 윤곽이 은은하게 드러난다. 모바일도 사물을 바로 터치한다.
소품을 누르면 내용을 가까이에서 보여준다. 모니터의 프로젝트는 어두운 작업 화면, 공책의 기록은 기록장, 실제 벽 메모와 인물의 소개는 프로필 종이로 구분한다. 모바일에서는 내용이 화면 아래쪽에 열린다. 방과 캐릭터의 움직임은 그대로 이어진다.

| 물건 | 메모 | 연결 |
| --- | --- | --- |
| 벽 메모·인물 | 소개 | 방 안의 프로필·경험 읽기 |
| 모니터 | 프로젝트 | 방 안의 프로젝트 목록·상세 읽기 |
| 공책·책장 | 기록 | 방 안의 글 목록·본문 읽기 |

장식용 소개 문구는 새로 만들지 않았다. 내용은 기존 메인·프로젝트·소개·글·사이트 설정 데이터에서 서버가 필요한 필드만 골라 전달한다. 이미지와 본문은 해당 화면을 열 때만 렌더링한다.

- `interactions.ts`: 물건의 절대 좌표 윤곽. 가로·세로 그림 좌표를 따로 보관한다.
- `data.ts`: 기존 콘텐츠를 메모용으로 선택하는 서버 진입점.
- `components/RoomInteractions.tsx`: 이미지 크롭에 맞춘 클릭 영역, 열린 메모, 화면 안 배치, 키보드·포커스 처리.
- `components/RoomNote.tsx`·`RoomReaders.tsx`: 화면 틀과 목록·상세·본문을 방 안에서 표시한다.

물건 위의 투명한 네이티브 버튼이 클릭 영역이다. 작은 터치 영역은 44px 이상으로 보완한다. Enter·Space로 열고, 닫기 버튼·Escape·바깥 클릭으로 닫는다. Escape와 닫기 버튼은 원래 물건으로 포커스를 돌려준다. 모션 감소 상태에서도 탐색은 가능하다.

이번에는 클릭·닫기·키보드 포커스·링크·모바일 위치만 브라우저에서 확인했고 `npm run build`도 통과했다. 발견한 오류인 **방 일시정지 중 메모가 투명하게 멈추는 문제**만 기존 검사 파일에 회귀 항목으로 추가했다. 방의 동작과 메모를 여는 UI의 동작을 구분해 해결했다. 전체 장면 검사나 성능 측정을 매번 반복하지 않는다.

## 동작 개발 (2026-10-30)

- 캐릭터를 고정된 의자·다리와 움직이는 상체·손목으로 나눴다. 호흡이나 자세 변경이 의자 전체에 적용되지 않는다.
- 기본 배치를 키보드 쪽으로 조정하고 손목 각도와 발·의자 접지 그림자를 보완했다.
- 특별 동작은 `preparing → holding → returning → working` 순서다. 650ms 타이핑을 멈춘 뒤 동작을 유지하고, 900ms 복귀 시간을 거쳐 타이핑을 재개한다. 전체 생각·스트레칭 시간은 각각 6.2초·6.8초다.
- 자세 전환은 220ms CSS 애니메이션으로 처리해 중간 블렌딩도 정지·재개할 수 있다. 상태·단계 스케줄러는 타이머 하나만 사용하고 비활성 시간은 남은 지속 시간에서 빼지 않는다.
- 화면 문구·내비게이션·새 이미지·의존성은 추가하지 않았다. 변경은 이 feature에 한정했다.

## 이번 수정 (2026-10-27)

- 임의로 추가했던 영문 브랜딩, 제목, 소개 카피, 감성 문구, 장면 번호, 헤더·푸터를 제거했다. 방을 화면 전체로 표시한다.
- 화면 카피를 임의로 채우지 않는다. 평소에는 방만 보이며, 열린 내용은 기존 콘텐츠를 사용한다. 사물의 기능 이름과 모션 제어 이름은 접근성 레이블로 읽힌다.
- 단순한 벡터 도형 배경을 새 일러스트로 교체했다. 나무 결, 종이·책, 천 주름, 잎 그림자, 창밖 풍경과 소품의 생활 흔적을 그림에 반영했다.
- 배경과 캐릭터는 별도 에셋이다. 캐릭터에는 타이핑·생각·스트레칭 세 자세가 있고 타이핑 손목은 별도 레이어로 움직인다.
- 세로 화면용 배경을 따로 제작했다. `<picture>`가 화면 비율에 맞는 그림을 선택하며, 캐릭터·모니터·주변 모션도 해당 구도에 맞춰 배치한다.
- 에셋 디코딩 뒤에 인트로를 시작한다. 스킵·세션 재방문·모션 감소·탭 비활성화·일시정지 처리는 유지한다.
- 고해상도 그림 로딩 중에도 방이 먼저 보이도록 같은 그림의 11~13KB 프리뷰를 아래에 둔다. 별도 로딩 문구나 블러 필터는 없다.

Next.js App Router / React / TypeScript를 유지한다. 그림은 정적 에셋이며, SVG는 레이어 정렬과 마스크에 사용하고 움직임은 CSS로 처리한다. 새 패키지는 설치하지 않았다.

이번 시각 수정은 실험 경로와 해당 feature·에셋에 한정했다. 기존 `/`, `/about`, `/projects`, `/blog`의 구현과 공통 스타일은 수정하지 않았다. 이전 단계의 `SiteShell`·부트 스플래시 실험 경로 분기는 유지한다.

그림의 생성 도구, 실제 저장 파일, 크기, 최종 프롬프트는 [`ASSETS.md`](../../../public/images/study-room/ASSETS.md)에 기록했다. 배경은 AVIF를 우선 사용하고 WebP를 대체 형식으로 제공한다. 캐릭터 스프라이트는 투명 WebP다.

## 동작과 현재 한계

- 기본 동작은 `typing`, 14~22초 뒤 `idle` / `thinking` / `stretching` 중 하나로 바뀌고 다시 타이핑한다. 같은 특별 동작을 연속 선택하지 않으며 타이머는 하나다.
- 타이핑 손목, 아주 작은 호흡, 햇빛과 화면 밝기, 커피 증기가 움직인다. 커튼 표현은 그림 위의 약한 빛 변화이며 천 시뮬레이션이 아니다.
- 특별 동작은 세 가지 그려진 상체 자세를 고정된 의자·다리 위에서 전환하는 방식이다. 모든 중간 프레임을 그린 애니메이션이나 관절 리깅은 아니다. 손·팔의 중간 동작을 그린 프레임은 이후 개선 범위다.
- 모션 감소에서는 정적 장면을 표시한다. 탭이 숨겨지면 타이머와 주변 모션을 멈춘다. 데이터 절약 또는 논리 CPU 2개 이하 신호가 있으면 주변 모션을 줄인다.
- 배경 소품은 그림에 포함되어 있다. 클릭 영역을 같은 좌표계 위에 배치했고, 소개·프로젝트·기록을 기존 페이지로 나가지 않고 방 안에서 읽는다.
- 컵 마시기, 상세 페이지, 오디오, 서버 기능, 실제 모바일 기기·Safari 성능 검증은 포함하지 않았다.
